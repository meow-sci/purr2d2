# Saber overlay and multiple EVA kittens

Purr2D2 starts disabled each session. A Harmony postfix on the native `Program.DrawProgramMenusHook` adds **Purr2D2 → Enabled**. Enabling activates the overlay; disabling hides UI immediately and queues world/resource cleanup for the next settled update. An off/on pair before that update retains the cleanup. Persisted slice assets remain registered independently of feature activation. The Settings button under the EVA rows toggles the shared blade length, volume, alignment, preferences and diagnostics window. Per-kitten settings and all actions use the overlay, with no F7 action shortcuts.

The overlay controls use the main ImGui viewport's background draw list, with alpha 128/255 fills and no windows, title bars or drag handles. They sit above the game scene and below every ImGui window, including other mods' windows, menus and popups. A top-right EVA list shows independently checked kittens and a small color swatch per row; the fixed black swing circle sits at the right side's vertical centre, with Ignite and Slice below-left and a somersault diamond below. The left Move circle has Force and Angry Force below-right. Layout follows the viewport and UI font scale. The list scrolls when necessary. Names clip before the swatches, whose hit areas follow the same row positions and scroll offset as drawing.

At base scale the swing radius is 132 pixels, its centre is 284 pixels from the right edge, and the slice radius is 27 pixels. Responsive scaling keeps both controls within small viewports. While selection is armed the slice circle reads `CANCEL`; the same queued action toggles selection off without starting a new stroke.

The work-area anchors and [panel layout](https://github.com/elevatorctln/KSA-Public-Telemetry/blob/90608fb465f87d6008208798cc4d20ed8182c9a0/Rendering/PanelHost.cs) follow the KSA Broadcast Telemetry Overlay, as documented in the local KSA modding skill. The background layer matches KSA's own `ImGuiHelper.GetMainOverlayDrawList()`. Draw lists supply no input handling, so the saber controls implement their own geometric hit tests rather than transparent square windows.

## Input and temporary pose

Narrow prefixes on Program.OnMouseButton, OnCursorPos and OnScroll consume game input owned by the overlay. New presses and hover wheel events yield when ImGui requests mouse capture, so windows covering the controls receive their input. Paired filters on the native ImGui backend consume only overlay-owned button and wheel events. Circular tests leave square corners click-through. A captured press keeps its release even outside the widget or over a window, while native camera and ImGui drags retain their own releases. A focus-loss hook clears capture even when the HUD is hidden. Overlay input also suppresses the slice picker for that frame, preventing the slice button itself from selecting a part underneath it.

Swatches open an ImGui color popup with a hue wheel and no numeric inputs. Popup gestures suppress the game's input route but pass through the ImGui backend, which owns the picker. ImGui composites the popup and settings window over the controls without custom exclusion rectangles. Settings-window gestures also pass through the ImGui backend and retain their native ownership outside the window until release. Swatch clicks never toggle equipment. Closing or hiding the overlay, changing control, boarding, losing focus or loading a world dismisses the picker; an already owned button release remains paired with its press.

The gesture snapshots grip and blade direction, maps pointer displacement into a bounded radial offset, and applies short response smoothing. Input and indicator drawing use the same travel radius: the full visible swing radius minus the marker radius, so the white marker can reach the circle edge. Horizontal movement adjusts lateral grip and yaw; vertical movement adjusts grip height and pitch. The existing arm IK still limits physical reach. Release eases back in 0.24 seconds and restores the original unnormalized direction exactly. Temporary offsets never write settings. Pause freezes motion; hiding the overlay, changing owner or loading a world releases the temporary pose.

## Kitten ownership

Each EVA object has one blade state, pose processor and audio owner. The controlled kitten's fields alias its record so existing slicing and contact paths remain scoped to that kitten. Switching control cancels an unfinished slice, but preserves other kittens' sabers. Checkbox changes are queued to the joined simulation handoff. Boarding/disposal removes the record, restores MMU visibility and stops owned sound channels. World/editor reset releases all records.

Each record also owns its color. New records cycle through red (143,16,16), green (13,81,1), yellow (49,49,5) and purple (98,9,96), divided by 255 for rendering. Assignment happens only during the settled EVA snapshot and resets with world state. Row edits affect only that kitten, even while unequipped or not controlled. Both blade drawing and point lights use the record's color. Each kitten's saber popup edits its own color and type; the Settings window contains only shared preferences and diagnostics. Individual colors and equipment remain session state rather than saved game data.

One shared renderer submits each posed saber and its light emitters. KSA's native hilt instancing copies the transform for each draw; separate renderer instances would conflict with shared render hooks. Noncontrolled kitten processors may publish poses, but only the main gameplay viewport refreshes the frame used to authorize a slice.

## Picker and validation

The target marker is larger, with green eligibility feedback and red rejection feedback. Native hover candidates remain available for red display without authorizing a cut. Click validation and queued/stroke-start reach checks remain unchanged. Hover reuses the native picker and does not scan meshes.

Managed checks cover bounded gestures, exact restoration, pointer ownership, hover rejection and per-kitten lifetime behavior. Host metadata checks validate input hook signatures. Actual appearance, mouse behavior, spatial audio and simultaneous rendering still require the game.
