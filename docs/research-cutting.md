# Cutting architecture

The current gameplay separates **Swing / Alt+F7** from **Select part to slice / Ctrl+Alt+F7**. The latter arms a cursor selection; clicking an in-range part locks it and starts a 1.24-second swing/recovery as soon as the blade is ignited. Ordinary Swing retains its 0.62-second timing. Animation does not wait for the worker to find a section or prepare assets. `SaberRuntime.AssistedSlice` aims from the hilt toward the clicked surface at the user's blade length while background preparation tries bounded varied sections. Breakup requires both prepared native assets and presentation of the final main-view swing pose. It consumes one commit cue on the first subsequent safe update. Preparation failures are reported after the full stroke, not used to interrupt it.

`PartSliceTargeting` reuses KSA's current-frame `MainViewport.PartPicker` and normalized cursor ray for exact part selection. Hover validation does not scan fleet geometry. If no native pick exists, clicking starts an incremental two-sided triangle-ray fallback, without constructing a cold BVH or selecting a nearest-part substitute. Both paths measure reach from the live blade base to the hovered ray hit, limited to `2 * Deployment * BladeLength`. There is no center-distance test or automatic extension. Fresh pose and reach checks run again after queued/fallback selection and before the stroke begins. Reach is not reimposed after a valid stroke. Ownership and transform checks remain in place before native replacement; crew presence does not block selection or commit. The flight-computer target does not constrain or cancel the cut. `SliceSourceCapture` copies model data in 256-triangle chunks with a 1.5 ms soft update budget. Geometry preparation and export are covered by [slicing research](research-slicing.md). Vessel mutation runs at the settled `PrepareFrame` seam after previous physics jobs have joined and before new jobs are dispatched.

Generated fragments put their complete picking mesh on an identity-transform visual subpart because native `Part.RayCastEgo` visits subparts. A narrow `Part` constructor postfix repairs older generated instances with a root-only picking mesh before a `PartTree` owns them. The repair does not modify old asset files or add a recurring hover scan.

`SaberContactProbe` is a separate read-only visual path. It emits sparks against static, dynamic and glass render meshes, including crewed targets. At 20 Hz it checks a cached contact triangle first, then uses a bounded resumable search of nearby mesh references. Native CPU arrays are read directly, with reusable candidate storage. The probe has no reference to the slicer and no destruction callback.

Autopilot, ring coverage, contact heat and automatic connection/failure cutting have been removed. Intentional controlled-kitten SWING contacts now use the bounded rendered-surface sweep described in [slicing physics](research-slicing-physics.md); idle and recovery contact stays cosmetic. There are no persistent contact scars; only short spark bursts and the actual sliced fragments' cooling cut caps remain.

Managed validation covers incremental selection and commit guards, nonblocking worker cancellation, final-pose presentation, ready/late results, exactly-once completion, contact sampling limits, multi-primitive search continuation, stale-contact rejection and allocation-free sustained contact. Native rendering, spawning and save/load still require in-game acceptance.
